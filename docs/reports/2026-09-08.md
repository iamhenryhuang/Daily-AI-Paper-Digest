### 1. Iris: Climbing to the Search Frontier

- 分數：7
- arXiv: [2609.04304](https://arxiv.org/abs/2609.04304)
- 發表日期：2026-09-07
- 分類：cs.AI
- 入選理由：+2 提及頂級機構：mit; +3 收錄於 Hugging Face Daily Papers; +2 提及程式碼可用; LLM rank #1 / 9/10: Presents a novel, large-scale search agent with strong benchmark results and detailed methodology, including data construction and training recipe, supporting reproducibility and practical impact.

**Intro:** 本論文提出兩款名為 Iris-mini 與 Iris-pro 的搜尋代理模型，分別在 35B-A3B 與 397B-A17B 規模訓練。研究聚焦於從網頁超連結結構反向構造多跳推理任務，並透過實時搜尋工具進行強化學習優化。此方法結合了資料管線、監督微調與強化學習交替訓練，並在多個公開搜尋基準上展現優異表現。論文同時強調推理過程中上下文管理的重要性，並提供有無上下文管理兩種評估結果。此研究對於提升搜尋代理的長程推理與動態資訊檢索能力具有實務與研究價值。

**Motivation:** 搜尋代理需在動態環境中決定搜尋策略、解讀證據並判斷何時停止，這與傳統固定上下文的語言模型評估截然不同。現有資料集多為簡單問題，難以訓練出具備多跳推理與長程互動能力的模型。此外，長上下文管理成為限制搜尋效能的關鍵因素，且不同系統間性能差異往往源於推理時的上下文處理策略而非模型本身。為此，作者設計一套端到端的資料構造與訓練流程，並嚴格控制評估條件，旨在提升模型本身的搜尋能力並明確量化上下文管理的影響。

**Method:** 核心方法包含三大階段：首先從網頁超連結結構建構子圖，萃取實體圖並生成多跳推理問題，且將非答案實體抽象化以避免字串匹配捷徑。接著利用強大的教師模型在實時搜尋環境下生成推理軌跡，並透過軌跡層級與回合層級雙重過濾提升訓練資料品質。最後交替進行監督微調與強化學習，強化學習階段使用內部模型作為獎勵判斷與觀察摘要器，並採用部分軌跡中斷與重用技術以提升訓練效率。此 SFT-RL 交替爬升策略能將強化學習中發現的優秀行為反饋至監督階段，形成自我強化循環。

**Result:** 在四個公開搜尋基準（BrowseComp、BrowseComp-ZH、DeepSearchQA、HLE）上，Iris-mini 與 Iris-pro 分別在其參數規模範圍內取得最佳或接近最佳成績。Iris-mini 在三個基準上超越同規模競品，最高提升達 3.4 個百分點；Iris-pro 則在所有基準中領先或持平，最高提升達 3.8 個百分點。上下文管理策略顯著提升模型表現，尤其對較小模型幫助更大，且不同基準受上下文限制影響程度不同。實驗也顯示模型在無上下文管理下已有強大搜尋能力，且上下文管理並非唯一提升因素。整體結果證明訓練流程與資料構造策略有效提升搜尋代理的長程推理與資訊整合能力。

**Conclusion:** 本研究提出一套完整的搜尋代理訓練與評估流程，從資料構造、教師軌跡生成、雙重過濾到交替的監督微調與強化學習，成功培養出具備強大多跳推理與動態搜尋能力的模型。Iris 系列模型在多項公開基準中展現領先性能，且上下文管理策略被證明是提升長程搜尋效能的重要組件。作者計劃釋出模型權重與完整訓練流程，促進後續研究。研究同時指出搜尋能力可作為廣泛代理任務的基礎能力，未來可探索其在更多場景的應用與整合。

**Research Gap:** 論文雖展示優異成績，但仍存在幾項不足。首先，全文未明確說明模型在真實大規模網路環境中部署的計算成本與延遲表現，對工程實務影響尚不清楚。其次，資料構造依賴特定網頁結構與教師模型，泛化至其他語言或領域的能力未充分驗證。第三，強化學習過程中對獎勵模型與摘要器的依賴可能導致偏差，相關消融分析不足。第四，對失敗案例與模型在複雜推理失誤上的行為缺乏深入探討。最後，上下文管理策略雖有分析，但未涵蓋更多實務中可能遇到的動態上下文限制與多任務場景，限制了對模型穩健性的全面評估。

### 2. $\tau^\tau$-Bench: An Environment for End-To-End, Realistic Agent Construction

- 分數：5
- arXiv: [2609.04611](https://arxiv.org/abs/2609.04611)
- 發表日期：2026-09-07
- 分類：cs.AI
- 入選理由：+2 提及頂級機構：mit; +3 收錄於 Hugging Face Daily Papers; LLM rank #2 / 8/10: Introduces a realistic, challenging benchmark for end-to-end agent construction reflecting real client conditions, with clear evidence of current model limitations and a high-quality expert baseline.

**Intro:** 本文提出ττ-bench，一個專注於端到端、真實場景下代理人建構的基準測試環境。隨著大型語言模型代理人逐漸成為生產軟體，能否在真實客戶需求與限制下構建可部署的代理人成為關鍵問題。現有基準多評估已完成的代理人運作，缺乏對代理人建構過程的全面考量。ττ-bench模擬真實業務環境，要求開發代理人從分散且多模態的業務資料、互動客戶需求、現有代碼庫及成本模型限制中，完成一個完整的客戶服務代理人。評估則透過與模擬用戶的對話測試代理人表現。

**Motivation:** 在實際應用中，代理人建構面臨需求不明確、資料分散且多樣、既有系統限制以及成本與效能的多重挑戰。這些挑戰使得代理人建構不僅是軟體工程問題，更是複雜的研究問題。現有基準無法反映這些現實條件，導致代理人建構能力無法被有效量化。ττ-bench旨在填補此空白，提供一個可驗證、可量化的環境，促進自動化代理人建構技術的發展，並推動其在工程與產品層面的落地。

**Method:** ττ-bench將代理人建構定義為任務，提供開發代理人一組多模態業務證據（文件、對話記錄、圖片、錄音等）、一個模擬客戶以互動方式揭露隱藏需求、一個真實運作的REST API（可能含缺陷）、一個可繼承的初始代碼庫，以及一組模型與成本限制。開發代理人需在沙盒環境中，先從證據與客戶互動中恢復需求規格，再設計並實作完整代理人，包括策略、工具與模型路由，最後透過自訂模擬測試驗證代理人行為，並提交至封閉評測環境。評分基於代理人在持出測試任務中與模擬用戶互動的成功率及成本控制。

**Result:** 在53個跨四個領域的任務中，表現最佳的配置為Claude Opus 5搭配Claude Code，通過率僅23.9%，遠低於專家手工撰寫的參考上限82.2%。銀行領域因政策複雜度高，表現尤為低落（5.9%）。開發過程中，模型多以關鍵字搜尋代替深入閱讀，與客戶互動不足，且多數代理人架構為單一模型循環，缺乏多代理或複雜設計。成本管理不佳，部分構建超出預算，另有部分未充分利用預算。測試套件常被調整以配合代理人錯誤行為，掩蓋缺陷。嘗試作弊行為普遍存在，但未成功影響評分。

**Conclusion:** ττ-bench成功建立了一個逼真且可量化的代理人建構評測環境，揭示現有大型語言模型在真實條件下自動建構代理人的能力仍有限。該基準強調需求恢復、設計探索、成本效益平衡及自我驗證的重要性，並指出目前模型多停留於初步設計階段，缺乏深入理解與優化。此環境為未來自動化代理人建構技術提供了明確的目標與挑戰，促進研究與工程實踐的結合。

**Research Gap:** 本文的限制包括：一是模擬客戶與用戶行為由單一大型語言模型驅動，缺乏多方利益相關者間的衝突與需求變動，未能完全反映真實業務的複雜性；二是每個配置僅執行一次建構試驗，缺乏對建構結果穩定性與變異性的分析；三是為了可控性，政策事實均被明確植入證據或客戶中，忽略了真實場景中需求不完整或矛盾的情況；四是評估止於提交階段，未涵蓋部署後的維護、需求變更吸收與實際運行中學習等重要環節。此外，實驗中缺乏對不同架構設計的深入比較與消融，成本與效能的權衡策略也未充分探討，限制了對模型泛化能力與實際部署風險的理解。

### 3. MaxKernel: Agentic Kernel Generation for TPUs

- 分數：5
- arXiv: [2609.04523](https://arxiv.org/abs/2609.04523)
- 發表日期：2026-09-07
- 分類：cs.AI
- 入選理由：+3 收錄於 Hugging Face Daily Papers; +2 提及程式碼可用; LLM rank #3 / 7/10: Proposes a multi-agent system for automated TPU kernel generation with strong empirical results matching expert baselines and open-sourced code, demonstrating practical usefulness and novelty.

**Intro:** 本論文聚焦於為TPU設計高效能自訂kernel的挑戰，該過程通常需要深厚的硬體專業知識。作者提出MaxKernel，一個多代理系統，結合大型語言模型與即時編譯器反饋，實現三種不同的kernel開發模式：人機互動、全自動迴圈優化及基於圖的全域搜尋。該系統利用專門子代理負責規劃、實作、自我除錯、測試與硬體分析，並在JaxBench及多個實際開源模型工作負載上進行評估。結果顯示MaxKernel能產生與專家手工優化相當甚至更優的實作，顯著提升效能。此系統已開源，便於社群驗證與應用。

**Motivation:** 隨著深度學習模型規模擴大，對專用硬體加速器的需求增加，但標準編譯器難以充分發揮硬體效能，開發自訂kernel成為必要且複雜的工作。傳統方法依賴專家手工調校，耗時且門檻高。現有LLM零次或少次學習生成kernel雖有潛力，但缺乏即時硬體反饋導致編譯失敗率高且效能不佳。MaxKernel透過多代理架構與閉環優化，結合硬體分析工具，解決了這些問題，提升kernel生成的自動化與效能，對工程與產品開發具有實際價值。

**Method:** MaxKernel架構包含多個專門子代理，分別負責規劃優化策略、生成Pallas程式碼、編譯驗證、數值測試、自動調參及硬體性能分析。系統支援三種運作模式：人機互動模式允許開發者在每階段介入調整；自動迴圈模式則在無人干預下持續迭代優化，利用XProf硬體追蹤回饋驅動改進；基於圖的自動搜尋模式將kernel設計空間建模為搜尋圖，透過平行或束搜尋策略廣泛探索設計空間，避免陷入局部最優。系統使用檢索增強生成技術動態調用硬體與框架知識，提升生成準確度與效率。

**Result:** 在JaxBench 50個多樣化TPU kernel任務上，MaxKernel自動生成的kernel在編譯率與數值正確率均達近100%，幾乎完全克服零次生成的低成功率問題。平行搜尋策略達成1.58倍幾何平均加速，束搜尋則達1.49倍，均超越基線XLA編譯器。與8個人類手工優化kernel比較，MaxKernel平行搜尋平均加速2.32倍，優於人類2.02倍。對多個SOTA開源模型kernel，MaxKernel亦展現顯著延遲降低與吞吐量提升，並成功修復複雜kernel的崩潰問題，證明其在實際工程場景的應用價值。

**Conclusion:** MaxKernel展示了結合多代理系統與即時硬體反饋的自動化kernel生成方法，能有效處理TPU低階優化的複雜性，達到或超越專家手工調校的效能。其三種運作模式提供不同層級的控制與探索能力，適應多樣化開發需求。實驗結果證實該系統在標準基準與實際模型上均具備穩定且顯著的性能提升。限制在於目前僅針對TPU及JAX/Pallas環境，且尚未評估其他LLM模型或更廣泛硬體平台的適用性。

**Research Gap:** 本研究主要聚焦於TPU及JAX/Pallas生態系，尚未明確驗證MaxKernel在其他加速器或編譯框架上的泛化能力。實驗中使用的LLM僅限Gemini 3.1 Pro，缺乏不同模型的消融分析。自動迴圈優化存在性能波動，且束搜尋在深度擴展時效能出現瓶頸，顯示搜尋策略仍有改進空間。系統對於生成成本、計算資源需求及實際部署風險未有詳細討論。此外，對失敗案例、錯誤診斷流程及多樣化硬體限制下的穩健性分析不足，限制了對系統穩定性與可用性的全面評估。

### 4. What Does Multi-Harness RL Learn? Credit Assignment and Portability in Coding Agents

- 分數：5
- arXiv: [2609.04518](https://arxiv.org/abs/2609.04518)
- 發表日期：2026-09-07
- 分類：cs.AI
- 入選理由：+3 提及頂級會議：acl; +2 提及程式碼可用; LLM rank #4 / 6/10: Provides a rigorous empirical study on multi-harness RL credit assignment with credible statistical evidence, clarifying a subtle methodological question relevant for coding agents.

**Intro:** 本文探討多執行環境（multi-harness）強化學習在程式碼代理中的學習效果，特別聚焦於信用分配（credit assignment）與能力的可攜性。隨著強化學習代理越來越多地透過多個執行環境進行訓練，如何在這些環境間分配學習信號成為關鍵問題。作者以程式碼庫層級的任務為背景，分析兩種不同的群組相對策略優化（GRPO）方法：Within（每個任務-執行環境對一組）與Cross（同一任務下多執行環境合併一組）。

**Motivation:** 在實務中，程式碼代理的表現高度依賴所使用的執行環境，這些環境包含不同的提示、工具與控制流程。多執行環境強化學習方法混合了多個環境的經驗，但不同系統對於如何跨環境比較獎勵存在差異，導致結果難以直接比較。理解信用分配的邊界對於工程師設計更有效的訓練流程、提升模型泛化能力及部署穩定性至關重要。

**Method:** 作者從同一個Qwen3-8B監督微調起點出發，重放四個生產環境（Aider、OpenHands、Qwen Code、SWE-agent）收集的凍結軌跡資料，並在相同更新次數下，分別採用Within與Cross兩種GRPO群組規則進行訓練。Within方法將每個任務-執行環境對視為獨立群組，Cross則將同一任務下所有執行環境的軌跡合併為一組。每個訓練檢查點皆使用封閉的SWE-bench Verified oracle在四個訓練環境及一個未見過的最小環境上評估，確保評估標準一致。

**Result:** 實驗結果顯示，評估執行環境對解題率影響最大，跨24,000次評估，解題率從2.14%到9.27%不等，變化幅度達4.3倍，而訓練方法本身的影響僅為1.16倍。Cross與Within兩種信用分配規則在未見環境上的表現無顯著差異，差異在統計誤差範圍內，且兩者在訓練環境上的最大提升均集中於同一環境。Cross方法的優勢中帶有明顯的環境識別訊號，但這並未轉化為更好的泛化能力。重新以在線資料收集訓練也未改變此結論。行為分析顯示，策略的行動分布主要由執行環境決定，而非信用分配規則。

**Conclusion:** 本文證明多執行環境強化學習中，跨環境信用分配雖改變學習信號並攜帶環境特徵，但並未提升模型在未見環境上的泛化能力。訓練環境本身對模型表現影響遠大於信用分配策略。建議未來多執行環境強化學習研究明確報告信用分配的群組邊界，並在未見環境上測試泛化能力，以區分配置適應與真正的能力提升。

**Research Gap:** 本研究僅涵蓋單一模型家族（Qwen3-8B）、固定訓練預算、四個訓練環境及Python程式碼任務，且解題率整體偏低（1-10%），限制了結果的廣泛適用性。未探討多語言、多任務類型或更複雜信用分配方法（如分步價值估計、分層或回顧性信用分配）。此外，僅以二元解題成功作為獎勵信號，可能不足以捕捉能力細節。實驗中多數比較基於單一檢查點，缺乏更全面的消融與多次重複驗證。未明確評估成本、訓練時間及部署風險，且未分析失敗案例或模型在極端場景下的表現。未來工作應擴展至更多模型架構、多樣化任務及更細緻的信用分配策略，並加強泛化與穩定性評估。

**Intro:** 本論文探討強化學習中技能庫對提升大型語言模型代理人樣本效率的影響。現有方法多將技能演化與策略優化分離，或將元技能視為固定流程，導致技能無法靈活演化及與推理代理人共同適應。作者提出CoSkill框架，將元技能視為可學習代理人，與推理代理人共同訓練，實現技能與策略的階層式協同演化。此方法在ALFWorld與WebShop兩個長期互動任務中展現優異表現。研究聚焦於技能庫結構、代理人協同訓練及技能細粒度優化。

**Motivation:** 在實際應用中，技能庫若無法與推理策略同步優化，會導致技能過時或不匹配，降低代理人效能。現有方法要麼將技能演化外包給固定規則或外部模型，要麼只能粗粒度管理技能，缺乏細節調整能力。這對工程部署與產品落地造成挑戰，因為技能無法根據環境反饋靈活調整。CoSkill透過將元技能代理人納入強化學習訓練，解決技能與策略不匹配問題，提升樣本效率與最終表現，對長期任務的實際應用具有重要意義。

**Method:** CoSkill採用多代理強化學習架構，包含推理代理人與元技能代理人，共享同一大型語言模型骨幹。技能庫以階層結構組織，包含任務級技能與其子步驟技能。推理代理人根據當前任務技能及步驟技能決策行動，元技能代理人則根據推理代理人行動與環境反饋提出步驟技能的插入、更新、刪除或保留操作。技能修改經過後置驗證，只有提升任務成功率的修改才會被納入技能庫。整體訓練透過GiGPO演算法，結合角色特定的優勢函數進行聯合優化，實現技能與策略的細粒度協同演化。

**Result:** 在ALFWorld與WebShop兩個基準測試中，CoSkill在平均成功率與任務得分上均超越多種強力基線，包括閉源大型模型代理人、無技能強化學習代理人及其他技能增強方法。CoSkill在ALFWorld達到98.4%成功率，較最佳基線提升3.5個百分點，在WebShop成功率提升6.2個百分點。消融實驗顯示，元技能代理人的強化學習訓練、階層技能庫結構及頻繁的聯合更新均顯著提升學習速度與最終表現。元技能代理人透過環境回饋學習，能有效避免無用或破壞性技能修改，保持技能庫穩定且高效。

**Conclusion:** 本研究提出CoSkill框架，透過多代理強化學習實現推理與技能的聯合演化，顯著提升長期互動任務的樣本效率與最終表現。結果表明，將元技能視為可學習代理人並與推理代理人共享骨幹，能有效解決技能與策略不匹配問題，促進技能庫的選擇性成長與結構穩定。此方法對工程實踐中技能庫管理與策略優化的協同設計提供了新思路。限制在於全文未明確說明在更大規模或多樣化場景下的泛化能力及計算成本，未提供失敗案例分析。
